# 开发过程：Python 驱动 → C++ 驱动（2026-10-21～22）

平台：RDK X5（8 核 Cortex-A55，Ubuntu 22.04，ROS 2 Humble，CycloneDDS），电动轮椅外挂系统里的 IMU 驱动。

## 1. 问题：驱动占了 10% 的 CPU

Python 驱动 `imu_ros2_device/wit_imu_driver` 长期占单核约 9.5%、RSS 46 MB；同一台机器上两路 LD06 雷达的 C++ 驱动各只占 4–5%、12 MB。

先量清楚时间花在哪：

| 项目 | 耗时 |
|---|---|
| 解析一次轮询的数据（约 48 字节，Mac 上测） | 13 µs |
| 一次 rclpy 定时器唤醒（板上用 pty 假串口实测） | 约 2800 µs |

解析只占约 1/200，CPU 几乎全花在 rclpy 每次唤醒的开销上。20 Hz 轮询时占 9%，50 Hz 时占 17.5%。所以换更快的解析代码没用，要换掉 Python 客户端库。

## 2. 方案比较：Rust 还是 C++

先用 Rust 写了零依赖的协议层试点，对拍一致后比较：

| | Rust（rclrs/r2r） | C++（rclcpp） |
|---|---|---|
| 去掉 rclpy 开销 | 能 | 能 |
| 内存安全 | 编译期保证 | 靠测试与审查 |
| Humble 上的成熟度 | rclrs 需从源码编，要 colcon-cargo 插件与 libclang；板上编译慢，交叉编译要另配链接器 | 系统自带，和其余 C++ 包同一套构建 |
| 维护 | 项目里多一门语言、一套构建链 | 与现有 C++ 包一致 |

CPU 收益两者一样，C++ 的集成风险小得多，所以选 C++。

## 3. 设计：行为与 Python 版逐项一致

- `include/x5_wit_imu/wit_protocol.hpp`：不依赖 ROS 的头文件，逐段对应 `wit_protocol.py`：
  - `FrameParser`：字节流按 0x55 帧头重新同步，校验和错前移 1 字节，帧时间按帧后剩余字节回推；
  - `FrameClock`：芯片日内时间映射到主机单调时钟，跟随漂移、处理跨午夜、复位和主机时间回退；
  - `decode`：单位换算到 m/s²、rad/s、rad、℃，欧拉角按 Z-Y-X 转四元数；
  - `SampleAssembler`：按帧到达序号配对加速度/角速度/姿态，不重复配对、不配过期值。
- `src/wit_imu_node.cpp`：节点名、参数、话题、REP-145（`data_raw` 的 `orientation_covariance[0] = -1`）、协方差、诊断字段名和取值格式都和 Python 版相同，监测端不用改。
- 轮询周期保持 20 Hz、每次最多读 4096 字节，和 Python 版一致，不改变时间戳行为。
- 串口：8N1、原始模式、非阻塞，打开后清空输入缓冲（与 pyserial 相同）。断线（POLLHUP，或可读却读到 0 字节）时退出码 1，由 launch 的 `respawn` 3 s 后重启。

## 4. 验证

1. **单元测试**：Python 的 `ClockTests` 和 `ProtocolTests` 移植成 `test_wit_protocol`（23 组），`NodeTests` 移植成 `test_wit_imu_node`（9 组，用 pty 假串口，在 ROS 域 199 跑，输出只收集、不发出）。
2. **差分对拍**：`test/replay_compare.py` 随机生成带噪声、翻转位、丢字节、插入垃圾、芯片时间跳变或重复、跨午夜、主机长停顿和时间回退的数据流，Python 原版和 C++ `wit_replay` 各处理一遍，逐行比较帧时间和样本值（容差 1e-8）。300 个场景、21.6 万行输出全部一致；这些场景共产生 4335 次校验错、867 次时钟复位，其中 57 个场景没有 TIME 帧。
3. **板上隔离编译**：先在 `/tmp` 单独编译、测试、对拍，不碰运行目录。
4. **CPU 对比**（`tools/bench_cpu.sh`）：pty 假 IMU 以 10 Hz 回放实采周期，两个驱动各跑 30 s：

   | | CPU（单核） | RSS |
   |---|---|---|
   | C++ | 0.77% | 20.6 MB |
   | Python | 7.9% | 58.8 MB |

5. **真 IMU 切换前后**（`tools/imu_check.py` 只读订阅）：

   | | Python（20 s） | C++（30 s） |
   |---|---|---|
   | `/imu/data_raw` | 10.03 Hz，最大间隔 114 ms，时间戳延迟 25.4 ms，倒退 0 次 | 10.03 Hz，111 ms，22.4 ms，0 次 |
   | `/imu/data` | 10.03 Hz，\|q\| = 1.0000 | 10.03 Hz，\|q\| = 1.0000 |
   | `/imu/mag` | 10.00 Hz | 10.02 Hz |
   | 加速度模长 | 9.824 m/s² | 9.825 m/s² |
   | 诊断 | level 0，0 次校验错误 | 相同 |
   | CPU / RSS | 10.4% / 50 MB | 1.3% / 12 MB |

## 5. 踩过的坑

- **诊断数值格式**：`std::to_chars` 默认挑最短写法，把 100000.0 写成 `1e+05`；Python 写的是 `100000.0`。改为和 Python repr 一样：1e-4 ≤ |v| < 1e16 用定点，否则用科学计数。是节点测试抓出来的。
- **角度换算的舍入**：`deg * PI / 180` 和 Python `math.radians`（`deg * (PI/180)`）的末位可能不同，改成同样的运算顺序。
- **参数错误要正常退出**：配置非法时构造函数抛 `std::invalid_argument`，`main` 要捕获并返回 1；否则会 `terminate` 崩溃退出，而 Python 版是正常报错退出。
- **串口断开的判定**：非阻塞读不到数据是 `EAGAIN`；`poll` 报 POLLHUP/POLLERR，或可读却读到 0 字节，才是设备拔出，与 pyserial 的判定一致。

## 6. 部署与回退（通用做法）

1. 把 `x5_wit_imu` 放进工作区，`colcon build --symlink-install --packages-select x5_wit_imu`，跑测试。
2. 在启动配置里把 IMU 的 include 从 `imu_ros2_device/imu.launch.py` 换成 `x5_wit_imu/imu.launch.py`。两者参数相同，可以互换。
3. 重启传感器服务，用 `tools/imu_check.py` 对比频率、时间戳延迟和诊断。
4. 回退：把 include 改回 Python 版即可，Python 驱动保留不删。
